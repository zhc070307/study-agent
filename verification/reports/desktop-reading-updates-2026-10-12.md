# 阅读、本地文件与更新复查

日期：2026-10-12（Asia/Hong_Kong）。

## 修改

1. 参考用户提供的 Codex 界面与 [VS Code 紧凑布局](https://code.visualstudio.com/docs/configure/custom-layout)：应用栏和文件标签栏均为 36px，PDF 控件压为 30px；完整路径、编译、改名、历史等放入文件菜单。Mac 将系统窗口按钮融入应用栏，Windows 使用系统标题栏覆盖层。打开多个文件时，标签横向滚动并保持当前标签可见。连续 PDF、缩放、页码与划词功能保留。
2. 文件菜单提供“用系统应用打开”“在文件夹中显示”。课程文件使用已落盘的课程路径；未整理材料创建有原文件名的预览副本。系统操作只接收文件身份与学期，通过应用私有授权解析路径，并检查它位于学习库内。外部修改不被覆盖，旧学期请求被拒绝。“下载”改为“导出副本”。
3. 新版后台下载并校验，安装仍由用户点击，忙碌或未保存修改不被更新打断。顶部更新按钮直接执行更新，不打开密钥设置。Windows 使用已有 electron-updater；未正式签名的 Mac 在应用内下载校验 `.dmg` 并打开安装盘，保留 Finder 替换步骤，不绕过系统签名检查，也不再打开 GitHub。正式签名后仍使用原生更新。

[Electron 明确要求 Mac 原生自动更新使用签名应用](https://www.electronjs.org/docs/latest/api/auto-updater)。当前没有发行签名凭据，因此 Mac 不是静默替换安装：每次打开下载好的安装盘后仍需拖入“应用程序”替换。旧版 Mac 用户须先安装一次 0.1.10 才能获得新的应用内下载方式。

- 12 项桌面检查（含路径边界）通过：Windows 真实下载器、Mac 本地 HTTP 下载、大小与 SHA-512、损坏下载和缓存拒绝、降级拒绝、失败不退出、重复操作抑制、忙碌与取消保留更新、发布文件校验。
- 完整浏览器学习路径、文件与聊天三轮交互、对话管理三轮、首次使用检查通过；验证菜单实际可用、正文起始位置、文件桥参数、顶部直接更新及未保存密钥／草稿保留。
- 使用临时学习库和模拟模型，没有付费模型调用或修改用户本机安装。

Mac 和 Windows 原生安装验证将由 0.1.10 构建执行。打包启动检查增加真实的文件夹定位调用，两平台均运行更新检查。未完成的构建不计为发布成功。

## 安装检查发现并修复的问题

0.1.9 的 Windows 打包应用检查在文件夹定位时发现：Python 把用户目录的 8.3 短名称解析成长路径，Node 的普通 realpath 保留了短名称，导致同一个学习库被误判为不同位置。该版本未发布。

改用两端一致的原生路径解析，并保留学习库边界校验。新增 Windows 实际短路径与长路径互用检查，以及其他平台符号链接、越界与非文件拒绝检查；修订版本为 0.1.10，重新进行原生安装验收。
