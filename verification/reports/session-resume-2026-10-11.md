## 确认的问题与修复

| 问题与触发方式 | 修复与验证依据 |
| --- | --- |
| SDK 重启后进程内会话表为空，却再次新建磁盘上已有的会话 | 有持久化服务时优先调用 `agents.resume()`；只在 `SessionPersistenceNotFoundError` 时新建。当前 provider、model、reasoningEffort、maxTokens 用于恢复。真实 SDK 进程与 HTTP/UI 检查均通过。 |
| 恢复失败被统一归咎于云端模型配置 | 改为提交失败与保留已有内容的说明；超时单独说明本次处理已停止。异常链仍保留，不把无依据的原因告诉用户。 |
| 提交等待超时后旧进程可能继续执行 | 超时先停止原进程，再结束本次请求。回归检查确认后续迟到内容不进入当前对话。 |
| 同一聊天在上一回合处理中仍可接纳另一个请求 | 按请求身份管理正在处理的回合，拒绝并发新请求；同一身份的确认重试不重复写入。旧请求的失败也不会结束新的回合。 |
| 启动时按停止仍可能提交问题 | 启动后重新核对回合身份；停止时在同一锁内结束回合并停止原进程。检查确认已停止的问题不会写为新的运行回合。 |
| 保存失败关闭编辑框；查看引用切走正在讨论的对话 | 保存成功后才关闭，失败保留输入；引用预览保留当前对话及问题，标题明确对话归属。 |
| 未发送问题、未完成作答和 PDF 位置不易继续 | 各对话分别保存草稿与滚动位置；作答草稿与已保存作答分开；PDF 页码、缩放与阅读位置独立保留。 |
| 同名文件、长对话和代码不易定位或复用 | 文件名与文件夹路径搜索、位置标识、路径导航与拖放归档；历史对话搜索、当前对话查找、消息与代码复制、再次编辑与引用提问。 |

损坏、占用与其他恢复错误继续报告失败，不能用创建新日志或删除历史来规避。会话损坏首行与第二个活跃写入进程的检查确认原日志未被覆盖；写入进程被强制终止后，原对话可以重新恢复。

## 三轮用户视角

1. **多个课程与大量材料。**同名文件显示完整位置，搜索跨当前学期的文件夹；可以从路径直接导航，选中文件拖入文件夹。移动后原文件身份、内容和关联保留，筛选关联材料时不丢失已选项。
2. **读到一半或写到一半。**预览另一份材料保留正在写的问题；保存失败保留修改；重新打开恢复 PDF 位置与未完成作答。草稿不自动变成作答证据，其他文件的更新不拆掉正在阅读的页面。
3. **用过一段时间的长对话。**可以搜索旧讨论并跳到匹配消息，复制解释或代码，把旧问题放回输入框；各对话的草稿与位置互相独立。发送失败后保留原问题，也保留发送后新写的内容；已进入历史的问题不会再作为未发送草稿自动恢复。

实际参考了 [DeepSeek Harness 的对话状态设计](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-conversation/README.md)与 [Codex 的文件和对话查找操作](https://developers.openai.com/codex/app/commands)。采用的剪贴板代码保留了 DeepSeek 的 MIT 许可和源码出处，见 `THIRD_PARTY_NOTICES.md`。其余交互按本项目现有界面实现。
