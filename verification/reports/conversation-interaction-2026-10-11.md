# 对话与文件交互复查

日期：2026-10-11（Asia/Hong_Kong）。使用临时学习库、Chromium 和模拟模型；没有调用付费模型或改动用户本机安装。

## 采用的实现

- [DeepSeek Harness 对话侧栏](https://github.com/deepseek-ai/deepseek-harness/tree/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-workspace)：常驻列表、新建、行内改名、搜索、归档和恢复。采用其紧凑列表的样式规则，适配课程文件关联与浅蓝配色。
- 同版本 `ui-primitives` 的 `useAnchoredPosition.ts`、`relative-time.ts`：实际纳入 `ui/harness-ui.mjs`，将 React 生命周期改为浏览器 DOM，保留菜单随滚动、窗口和内容尺寸变化重新定位、视口边界限制，以及时间分桶；补充键盘导航、Escape 和点外部关闭。
- [Codex 对话生命周期](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/request_processors/thread_delete.rs)：参考停止活动、清理持久记录、通知其他窗口的顺序。未复制其 Rust 服务。归档为主要收纳方式；删除仅为可选操作。
- PDF 使用已随包提供的 PDF.js `PDFViewer`、`PDFLinkService` 和 `EventBus`，替代自写单页切换，提供连续阅读、按需渲染和可选择文字。

DeepSeek Harness 的完整应用依赖自己的宿主与会话服务。本项目直接采用上述可用实现，继续使用已有学习库与 SDK；没有引入另一套服务器或要求用户下载其应用。MIT 来源、版权和完整许可已记录于 `THIRD_PARTY_NOTICES.md` 与代码头。

## 最终界面

对话列表紧挨聊天区，放在同一侧；文件桌面、任务和阅读预览在另一侧。聊天默认获得较多宽度，也可展开。列表不通过管理弹窗打开。

输入区改为随文字增长，压缩头部与消息间距。删除固定的“整理文件／组织练习”按钮、重复标题和“回到最新”浮层。桌面按钮返回真正的根目录；展开聊天后关闭助理不会留下空窗口。

## 三次用户视角复查与验证

| 视角 | 发现与修改 | 验证 |
| --- | --- | --- |
| 第一次使用、找回旧讨论 | 对话原来只有文件身份，缺少独立新建和管理。增加对话记录并迁移旧身份；列表支持新建、搜索、改名、归档和恢复，归档保留草稿和模型历史。 | `chat-management.cjs` 第一轮：真实 HTTP 与 SDK，独立新会话、行内改名、归档只读和恢复后继续；菜单键盘操作、边界及滚动跟随。 |
| 连续使用、失败与重启 | 对话删除不能只删界面消息；迟到保存和另一个窗口可能把旧数据带回。现在先关闭 SDK，按已有路径编码和写入锁移除其持久记录；数据库保留删除标记，拒绝迟到写入。课程文件、任务和作答不随对话删除。 | 第二轮：忙碌时拒绝、取消及确认删除、检查 JSONL 实际移除、双窗口同步、迟到草稿拒绝、重启后隔离。归档恢复仍保留历史。 |
| 一边阅读一边提问 | 头部和输入区占用过多空间、无意义按钮遮挡、PDF 无法滚轮跨页。压缩布局、扩大聊天并改用连续 PDF 阅读。复查中还发现选择消息文字时短回复随后增长会继续跟随，现在选中文字也暂停跟随。 | 第三轮：实际检查列表和聊天相邻、文件在另一侧、聊天主宽度、输入框增长与展开／隐藏、根目录导航和窄窗口。`interactions.cjs` 用鼠标滚轮跨 PDF 页，重开恢复阅读位置。 |
