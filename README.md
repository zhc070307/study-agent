# Study Agent

一个独立的学习 agent 项目。复用开源 agent harness，以代码管理学习流程，并提供由桌面和助理组成的浏览器 GUI。

当前阶段：已接入精简的 DeepSeek Harness，复用现有学习账本；材料处理、反馈出卷、计划、复测、课程核对和长期记忆流程均已接入，可保存、恢复和修改。桌面与助理的 GUI 交互原型已实现，尚未连接模型和学习服务。当前只在云端验证与修改 GitHub，不安排本机部署。

## 已确认的方向

- 本项目独立开发；现有自用 Study System 继续运行。
- 用户已使用 DeepSeek，不再安排额外的真实模型使用测试；开发检查继续验证接入、证据与恢复机制。
- 当前开发在云端工作区进行，代码与设计修改提交到 GitHub；不安排本机安装或部署。托管方式另行确定。
- GitHub 仓库先设为私有。
- 通过浏览器使用 GUI；主界面包含存放文件的桌面和助理对话框，特定任务界面包含文件和方便提问的对话框。助理负责整理文件、组织练习和回答问题。
- 第一版业务范围覆盖本机现有学习服务的内容；实现可分步推进，不将某条候选流程当作全部范围。
- 复用开源 harness 的模型调用、会话和工具执行能力。已采用固定版本 DeepSeek Harness。
- harness 管理流程阶段、上下文装配、前置条件、状态转换、证据保存和中断恢复。模型负责理解、建议、生成与批改。
- 流程融入 harness，同时允许模型根据用户要求修改 harness 中的流程定义和相关执行代码，使修改后的流程实际生效；不把模型的作用限制为在固定流程中填充内容。
- 系统规范模型检查材料、保存依据和核验结果，不替用户规定学习顺序。阅读与练习可以自由安排，任务依赖必须有具体依据。
- 课程方法需要根据材料和学生沟通确定；不把当前学期的课程名单、题源或节奏写入通用流程。
- 笔记写作和笔记核验、选题编排和试卷核验分别承担自己的职责。风格与教学要求由相应阶段提供给模型。
- 真实错误与复测必须关联作答证据；材料到达、讲解或发卷不等于掌握。
- 程序与个人数据分离。课程材料、作答、数据库、运行记录和密钥不上传本仓库。示例数据须不含个人资料。

## 现有服务的业务范围与实现依据

以下清单已对照仓库内 `study-system/` 源码、CLI、工具与 Skill 核对。它是现有服务的功能基线；具体课程名单、教材、节奏与例外仍属于学期和课程数据。

| 业务 | 现有能力与入口 |
| --- | --- |
| 学期与课程管理 | `study` / `workspace.py` 选择独立学期账本；`course add/setup` 注册课程并建立目录和 `COURSE.md`。课程方法由材料分析和学生沟通形成，程序不自动选择方法。 |
| 材料处理 | `material scan/inspect/claim/release/close` 发现文件变化、跟踪处理状态与回执；结合录音、转录、课件和正式要求核对实际范围，承接笔记与任务。扫描不证明材料已读或课程已讲。 |
| 当前上下文与日历 | `context now/course` 按层装配全局与课程上下文、材料事件、周池、错点和状态；macOS `calendar-events` 只读获取日程，学习判断由上层 agent 完成。 |
| 任务与学习计划 | `task` 管理任务身份、完成条件、证据、依赖、取消和恢复；`pool` 管理周池，`today` 选择当日任务，`view` 生成清单并同步勾选。任务完成与知识掌握分别判断。 |
| 课程状态核对 | `course state-status/state-reviewed` 核对账本与 `COURSE.md` 的版本；`map-review/map-reviewed` 管理材料地图复核。程序检查版本一致性，agent 核对学习含义与范围覆盖。 |
| 笔记制作与验收 | `study-notes` 规定输入准备、知识正文写作、图形版式、编译、逐页检查和修订；`delivery.py` 保存写作依据与核验回执，`lecture_note_quality.py` 提供辅助检查。现有 pi 作者与 Codex 编译分工属于参考实现，新项目模型配置尚未确定。 |
| 练习与考试复习 | `study-system` 规定官方练习、持续概念检测、反馈与复测的承接；`study-worksheets` 规定自组巩固卷和复习卷的证据草案、选题、题源核对、去重、题量负担与逐页验收。采用哪些方法由课程约定决定。 |
| 作答、错点与复测 | `assessment record/list/retest` 与 `assessment.py` 保存 assessment、learning_issues 和关联结果，保留初次错误及复测历史；后续选题读取统一账本。批改与诊断依赖真实作答及 agent 判断。 |
| 行动记忆与恢复 | `memory` 维护全局行动记忆及语义整理检查点；课程快照、数据库备份和归档支持回看与恢复。`lifecycle.py` 在启动、提示、工具操作、结束和中断时提醒核对，并恢复未完成的清理。 |
| 交付、维护与自动触发 | `delivery_review.py` 的 prepare/accept 核对依据、版本、页码记录和成品哈希；`finish_work.py` 在持久成品与回执存在后清理临时工作目录。课程约定的定时检查由宿主自动化触发，源码快照不包含现有自动任务配置或独立调度服务。 |

现有业务主要沿以下流程衔接：

- 新课程：注册与建立入口 → 分析材料并沟通方法 → 保存课程约定 → 建立实际需要的任务与完成条件。
- 新材料：发现变化 → 领取并检查材料 → 更新范围及课程状态 → 制作或复用笔记、承接正式义务与练习 → 保存处理回执。
- 日常学习：同步勾选 → 装配上下文 → 核对课程状态 → 选择周池与今日任务 → 执行或接收学生反馈 → 更新账本和视图。
- 反馈与练习：保存作答及诊断 → 关联错点、剩余任务和复测 → 按证据制定出卷草案 → 选题与核验 → 保存交付证据并清理 → 等待独立作答。

现有程序提供持久状态、事务和部分前置检查；课程判断、写作、选题、批改以及实际内容和视觉核验仍由 Codex 按 Skill 执行。核验字段与哈希完整不证明语义正确。新 harness 需要承接这些阶段并落实流程约束，不能仅把 Skill 文本交给模型就视为接入完成。

## 流程执行与修改

用户要求的方向是：harness 执行学习流程，模型也有能力依据用户要求修改 harness 来调整流程。阶段、分支、顺序、前置条件、上下文和工具组合应可随需求演进，而非固化为永远不变的流程。

当前实现有一个学习插件、原领域入口、桌面服务和一份初始流程定义，分别位于 `harness/study.ts`、`harness/worker.py` 和 `harness/flows.json`；剩余业务操作在 `harness/services.py` 中直接复用原服务。复用原账本和交付检查，不再另建模型循环、会话系统或工具框架。

模型使用学习读取、执行、流程修改三个工具，并通过一个桌面工具读写文件、整理目录、组织任务和制作 PDF。用户表达学习需求即可，不需要填写技术配置。模型可以修改课程或通用流程的说明、证据依赖及 Python 执行代码；新增代码必须提供输入和预期结果示例，通过检查后才能启用。

流程定义的列表顺序不构成执行顺序。只有显式的 `after` 表示模型操作的证据依赖，例如先有选题依据再核验成品。阅读笔记和做练习不是默认前后关系；材料处理只要求模型检查内容、按需求接续实际任务并保存回执，可以复用已有工作或不新增任务。

修改和运行所用版本保存在学习账本中，重启后仍生效。新运行采用当前版本；正在进行的运行保留原版本，按用户要求可切换尚未完成的操作。已完成记录和原始输入不改写；修改失败保留原流程，支持恢复上个版本。重复调用不重复登记作答或任务。

执行代码按可信应用代码运行。独立进程、临时目录和超时用于检查与恢复，不是任意代码的安全隔离。示例验证不证明教学判断正确；真实作答、内容检查和逐页核验仍由模型依据材料完成。

## 已采用与保留的能力

| 能力 | 实现选择 |
| --- | --- |
| 模型调用、会话历史和恢复 | 采用上游实现。 |
| 工具校验、取消、执行记录和插件卸载 | 采用上游实现。 |
| 读写文件和调用原学习服务 | 采用上游持久 shell，使用独立学习目录和同一账本。 |
| 学习任务、错点、复测、周池、今日计划、记忆、备份和交付检查 | 保留现有领域代码；上游没有相应学习业务实现。 |
| 学习操作进度、证据与可持久修改的流程 | 新增小型学习插件；上游动态插件和多 agent workflow 不具备这些完整能力。 |

运行组合保留模型、会话、工具、shell 和学习插件，关闭无关的标题生成、MCP 资源、后台 jobs、包清单和 PowerShell 插件。完整上游源码作为固定版本 submodule 保留，便于核对与升级。GUI 通过云端 Web 入口接入同一运行组合；当前不加入模型浏览器工具、多 agent 编排或额外插件管理界面。

新文件先记为未知类型。模型读内容后通过 `material classify` 登记类型与依据；所属课次也需明确登记，不再按文件名、扩展名或日期猜测和归组。

## 一个项目、一个入口

现在以 Study Agent 作为唯一项目入口。`vendor/deepseek-harness/` 是项目内部的运行底座；`study-system/` 是被复用的学习服务源码，二者共享学习目录与账本。目录分开用于维护上游和领域代码，不是两套应用。

```bash
./study-agent setup                         # 云端开发依赖
./study-agent check                         # 独立临时数据检查
./study-agent --data /path/to/study-data     # 统一 SDK 运行入口
./study-agent service --data /path/to/study-data --json course list
```

三个模型工具统一读取、执行和修改下列流程：

| 流程 | 保存与核对的内容 |
| --- | --- |
| 材料处理与反馈出卷 | 保留原有材料分类、任务承接、原始作答、选题依据与交付核验。 |
| 日常计划 | 同步已有勾选，读取全量任务与课程事实，按需求保存周池、今日选择及理由，生成今日、周和剩余任务清单。不预设用户学习顺序。 |
| 复测 | 关联原错点和真实复测作答，逐项保存结果与历史；再次失败或不确定时重新标为待处理，不自动完成学生任务。间隔由课程和用户约定决定。 |
| 课程核对 | 核对文档和账本版本，保存事实说明；改写文档前保留旧版，拒绝使用过期核对结果；材料地图复核可单独登记。未知授课范围保持未知。 |
| 长期约定与恢复 | 保存行动记忆及整理依据，保留旧版；中断恢复接续原步骤，拒绝用旧版本覆盖新的约定。 |

计划和记忆是全局流程，无需创建虚构课程。课程流程继续按课程保存。清单生成失败可从已提交计划继续；恢复清单前先同步学生反馈。账本通过原 SQLite 备份能力保存最新提交状态，未提交的文档和记忆改写通过小型恢复记录恢复旧内容；出现另外修改时保留记录供核对，不覆盖新内容。

云端独立 Harness 验证副本已确认没有独有代码，整理后只保留仓库内部固定版本。历史 `study-system/study` 和 `harness/run.py` 保留为内部兼容入口，开发和后续界面统一使用项目根目录 `study-agent`。

## GUI：桌面与助理

用户已确定两部分框架。桌面存放和展示文件；助理整理文件、组织练习和回答问题，后续接入现有 harness 和学习服务。界面尽量删减：不设宣传口号、装饰印章、英文引导、长篇欢迎说明或重复提示。以下设计部分已在交互原型中实现，业务接入仍待完成。

### 主界面

- 左侧为桌面，右侧为可调整宽度、可收起的助理对话框。文件区只显示文件夹和新建文件夹入口；文件夹显示清楚的图标、名称和文件数，打开后显示简单文件列表及添加文件入口，不设文件卡片或课程筛选。桌面另显示任务清单，可勾选并打开相关文件；阅读与练习任务没有默认先后或解锁条件。
- 文件打开方式参考 Codex：工作区顶部常驻“桌面”和已打开文件的标签，点击文件在同一区域预览，可切换或关闭标签。打开文件不跳到独立页面，也不重复显示大标题和引导说明。
- 文件夹内支持选择、重命名、移动和调整文件顺序。用户放置的位置保留，文件顺序不表示学习依赖。
- 上传或拖入文件后即显示真实接收状态。未知课程、内容类型保持待判断，助理读取内容后再整理；不按文件名推断业务含义。移动和改写保留恢复记录，历史引用依靠文件身份继续有效。
- 助理可围绕全局桌面或选中的文件工作。输入框上方显示实际关联的文件，允许用户增删；选中不表示文件内容已经被模型读取。支持“整理这些材料”“用这些内容组织练习”等自然语言请求。
- 助理的成品保存为桌面文件，对话中提供可打开的预览；操作结果显示简短说明和实际状态。处理中可停止或补充要求，中断后保留已经保存的结果。

### 特定任务界面

- 打开文件或进入练习后，左侧为文件工作区，右侧继续提供助理对话框；任务界面支持并排查看题目、笔记、作答及反馈。返回桌面时保留文件位置、阅读位置和对话。
- 选中文字、公式附近的段落或页面区域即可提问；问题带上可见的文件、页码和选区引用。无法提取的内容明确说明，可使用用户提供的页面图像，不假装已读。
- 练习支持上传或输入作答、请求提示、提交批改和查看反馈；答案与反馈按需展开。阅读与练习随时切换，不设默认先后或解锁条件。
- 同一任务保留对话，跨任务切换时清楚显示当前关联对象。通用约定与课程记忆由现有账本提供，不把所有历史对话自动附到每次请求。
- 批改和解释可定位回材料或原始作答；任务完成与知识掌握分别呈现，复测记录保留历史。界面只展示实际保存的状态，不用模拟进度代替事实。

### 采用熟悉的界面

- 参考 Codex 的成熟布局和文件操作，采用中性色、简单文件夹、标签页和标准预览区，不加入装饰性封面或自创的视觉隐喻。所有拖动都有点击操作。
- 桌面展开为文件工作区时保持视觉连续；专注时可收起助理，需要提问时原位展开。窄屏可在文件与对话之间切换，并保留当前内容。
- 今日事项、学习记录和课程约定按需打开，不占据主界面的文件区域。用户直接表达约定，助理修改真实流程；界面以简短说明展示影响范围、生效状态及恢复入口。
- 桌面与任务界面使用稳定的布局和同一组文件操作。模型可调整流程、任务和产物，不在普通学习操作中随意改变导航或要求用户配置流程图。

### 当前可运行实现

桌面与助理已经接通，入口为 `./study-agent web`。页面由 `harness/web.py` 提供，并使用原 `sdk-minimal` 的持久进程、模型循环与会话恢复；没有另写模型循环。上游源码仍固定在原验证版本。新工作区从空桌面开始；`ui/samples/` 只用于隔离检查，不冒充用户材料，也不作为固定练习塞进实际对话。

- 文件、文件夹、真实任务、对话、草稿与原始作答保存在指定的独立数据目录；刷新、停止与服务重启后继续保留。文件内容按版本保存，重命名和移动保持身份，源码编辑可恢复旧版。文件修改有版本冲突检查，重复工具操作不重复写入。
- 桌面任务直接复用原 SQLite TaskService。学生勾选记录实际确认完成，取消勾选重新打开任务；模型交付任务不能靠学生勾选替代核验。任务完成不证明知识掌握。作答保留历次原文，反馈、错点与复测继续使用原领域服务。
- 文件上传或拖入后保存在云端，支持 Markdown 正文／源码、LaTeX 源码、文本、PDF、常用图像与音频；文件上限 20 MB。不支持的格式如实提示。文件可下载。格式识别只选择阅览方式，不猜测课程、学习意义或授课范围。
- 助理请求带上真实文件身份、版本和选区／作答；工具读取完整材料后决定如何帮助。整理和出题不再调用固定示例；保存的产物直接出现在桌面和对应对话中。处理中可以补充要求或停止，停止保留已经提交的结果。
- 桌面文件按明确课程和位置 `publish` 后供原材料扫描与回执使用，不从文件名推断类型；课程目录中另有修改时保留两个版本并报告冲突，不覆盖原文。课程登记、COURSE.md、计划、记忆和真实证据继续由原服务维护。

PDF 使用上游同版本 PDF.js 6.3.289 与官方文字层，支持翻页、缩放、划词及页码引用；Markdown 和源码也支持选区旁提问。没有文字层的扫描 PDF 不凭空提供选区，助理可通过实际页面图像阅读；尚未加入 OCR。Markdown 采用 Marked 16.4.2 与 DOMPurify 3.4.11，清理活动内容，图片只显示替代文字，不自动加载第三方资源。第三方许可保留在 `ui/lib/`。

### LaTeX 与 PDF 交付

LaTeX 源码支持编辑、编译及源码／PDF 切换。助理修改源码后可编译；用户手动编辑 LaTeX 保存后也会编译。云端使用 XeLaTeX 与 latexmk，关闭 shell escape 和用户 latexmk 配置；附件按实际需要显式指定。编译日志、源码版本和每次结果保存，编译期间源码变化会拒绝覆盖当前成品；失败保留上一版 PDF。

编译成功只显示“待核验”。助理使用上游的图像能力检查与持久附件服务读取真实页面，逐页核对来源和版式，再保存核验。模型不支持图像时拒绝视觉验收，不能声称已经看过页面。课程正式笔记与练习在写作前保存真实依据，继续复用原 delivery.prepare／accept 的课程版本、草案、来源、逐页说明及成品哈希检查；过期依据或未通过页面拒绝验收。普通说明 PDF 与课程正式交付区分，不据此完成学习任务。源码、历史版本和原始作答保留，不沿用旧的本机 pi 分工或删除可恢复源码的做法。

## DeepSeek Harness 验证结果

考察版本固定为 [`5badb15009ae1756c3afe0ae0cef1faafc290ccc`](https://github.com/deepseek-ai/deepseek-harness/tree/5badb15009ae1756c3afe0ae0cef1faafc290ccc)，仓库版本字段为 `0.2.1-alpha.1`。环境为 Linux x86_64/glibc、Node 24.19.0、pnpm 11.19.0（上游声明 pnpm 11.7.0）。API 仍处于 pre-stable 阶段，后续升级需显式复核接口。

运行了 6 个定向测试文件，共 218 项，全部通过：上游工具执行与并发策略、AgentLoop 持久会话恢复、动态插件更新失败回滚、Plugin Manager 的 Loader 重载，以及本项目的临时 Python 账本桥接。桥接验证了实际模型循环中的工具调用能保存学习任务，重建 Context 后能恢复历史；新插件版本将下一项任务从笔记变为练习，原账本与会话历史保留。直接通过 Python 领域操作完成没有证据的任务仍被拒绝；卸载桥接插件后工具消失。

模型循环测试使用脚本化 MockAdapter，插件修改由验证程序提供。此外，通过支持的 `dsh --profile sdk-minimal` 启动实际 profile，SDK initialize 返回正常的 `deepseek-harness-sdk-runtime` 身份，shutdown 返回正常并以状态码 0 退出。此握手证明该 profile 能启动并解析模型配置，不证明真实模型能正确理解用户要求、编写修改或判断教学内容。当前没有配置 DeepSeek API 凭据，真实推理请求尚未进行；后续已用脚本化模型完成 GUI 到 SDK、流程修改与持久写入的联调，仍不代表真实模型能力验证。

完整 monorepo 安装在当前网络环境中无法获取文档预览所用的 SheetJS tarball。定向验证改为安装所需插件依赖闭包，未替换该依赖或改变上游 lockfile。云端 Node 缺少附带开发头文件；使用同版本官方 Node 头文件及上游编译参数构建 flock 模块后，会话恢复测试通过。复现脚本安装时跳过生命周期脚本，只显式编译验证所需模块；这不是完整产品构建验证。

复现定向验证（Linux x86_64/glibc，需 Node、pnpm、Python、Git、curl、tar 和 C 编译器）：

```bash
bash verification/deepseek-harness/run.sh
# 或复用已经检出的固定版本：
bash verification/deepseek-harness/run.sh /path/to/deepseek-harness
```

SDK profile 握手另行复现：在固定版本 checkout 中运行 `pnpm --filter '*' --filter '!@deepseek-ai/dsh-client-ui-sidebar-documentpreview' install --frozen-lockfile --ignore-scripts`，然后从本项目运行 `python3 verification/deepseek-harness/sdk-smoke.py /path/to/deepseek-harness`。它使用临时 Harness home，只初始化和关闭 SDK，不发送推理请求；文档预览插件未安装，不代表完整 Web 应用验证。

脚本默认在临时目录获取固定版本，测试使用独立临时账本与 Session 目录；传入已有 checkout 时会安装依赖、构建 native 模块，并临时加入随后移除的验证文件。验证代码不是新产品的流程实现。

接口核对的关键结论：

- Cordis plugin、`agent/pre-step`、`agent/request`、工具执行管线及 `agent/turn-stopping` 可用于阶段上下文、前置检查与收尾。业务前置条件还需在执行领域操作的入口落实，不能只靠 prompt 或工具隐藏。
- Session JSONL 可以恢复模型历史和处理中断的调用；它不自动恢复学习流程进度，也不保证与 Python SQLite 的业务写入原子提交，需要自己的操作身份、幂等与对账。
- 上游 `workflow` 主要是模型编写的多 agent 编排脚本，不是现成的学习业务状态机；不能直接替代学习流程的持久状态与证据检查。
- 动态 Cordis 定义只在当前进程、当前 Session 内存在，重启会丢失；当前模型工具 `cordis_inspect_*` 只读，不能创建动态定义。持久安装与配置更新使用 Creator 模式的 Plugin Manager。
- Plugin Manager 改动作用于整个 profile；开启 HMR 时可立即加载，未开启时需重启。headless/SDK 默认关闭 HMR。Host 插件运行在进程中，动态 runner 的 VM 也不提供安全隔离，不能宣称任意生成代码可安全热替换。
